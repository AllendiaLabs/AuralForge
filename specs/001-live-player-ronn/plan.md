# Implementation Plan: The Live Player & RONN (Phase 1)

**Branch**: `001-live-player-ronn` | **Date**: 2026-08-19 | **Spec**: `specs/001-live-player-ronn/spec.md`

**Input**: Feature specification from `specs/001-live-player-ronn/spec.md`

## Summary

Build a VST3/AU audio effect plugin using JUCE + LibTorch (C++ API) + Dear ImGui that processes audio through a configurable Temporal Convolutional Network with real-time parameter control, weight randomization, and a read-only Blue node graph UI. No training or Python backend required — all inference is performed via `torch::nn` modules in C++.

## Technical Context

**Language/Version**: C++17

**Primary Dependencies**: JUCE 8.x (audio plugin framework), LibTorch (C++ PyTorch runtime), Dear ImGui + imgui-node-editor (node graph UI)

**Storage**: DAW state serialization via JUCE `getStateInformation`/`setStateInformation` (binary blob with parameters + weight tensors)

**Testing**: JUCE AudioPluginHost for integration testing; Steinberg VST3 validator; Apple `auval` for AU validation; GoogleTest for unit tests on DSP/model components

**Target Platform**: macOS (VST3 and AU) — Phase 1 only

**Project Type**: Audio plugin (VST3/AU effect)

**Performance Goals**: <7 ms latency at 256-sample buffer on Intel i7; 60 FPS UI; weight swap <100 ms

**Constraints**: Zero memory allocations on real-time audio thread; atomic pointer swap for weight changes; causal processing only (no look-ahead)

**Scale/Scope**: Single plugin, ~15–20 source files, 1 TCN model architecture

│   ├── params/

**Structure Decision**: Single JUCE plugin project rooted at `AuralForge/`. Source organized into `dsp/` (audio/model), `graph/` (node visualization), `params/` (DAW parameters), and `ui/` (ImGui integration). This mirrors ML Forge's separation of engine/graph/ui but adapted for C++/JUCE.
